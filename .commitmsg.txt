feat(platform): add CrewAI coordination, optional MySQL, alerts and observability

Implements the feasible parts of the 15-phase platform-engineering mission.
Everything that could not be executed is reported honestly in
reports/audit/SNMK_PLATFORM_ENGINEERING_EXECUTION_REPORT.md.

Phase 2 - CrewAI coordination:
- core/crew_coordinator.py declares 22 specialist roles with bounded
  execution, retries, file-conflict guards, history and timeouts.
- CrewAI 0.203.2 is installed and imports, but the coordinator runs in
  "direct" mode unless SWA_CREWAI_ENABLED and a provider key are present.
  The API reports crewai_executed: false rather than claiming execution.

Phase 3 - tool registry:
- core/dev_tool_registry.py measures 28 tools with six honest statuses.
  Current host: 7 Operational, 7 Configured, 14 Not Available.
- Installed SQLAlchemy, Alembic, PyMySQL, prometheus-client, OpenTelemetry,
  Ruff, Black, Mypy and CrewAI in the venv. Semgrep was isolated in its own
  venv because it pins OTel ~=1.37 while FastAPI needs >=1.44. pip check is
  clean after repairing the conflict CrewAI introduced.

Phase 4 - MySQL:
- core/mysql_adapter.py adds an opt-in MySQL backend with pooled
  connections, retries, TLS settings and real telemetry queries. SQLite
  remains primary; no tables were migrated or dropped.
- Alembic scaffolding refuses to run unless SWA_DB_BACKEND=mysql. No MySQL
  server exists on this host, so status is "Not Available", not "Operational".

Phase 8 - alerts:
- core/alert_manager.py with deduplication, suppression, lifecycle actions
  and honest delivery reporting (DELIVERED only on channel confirmation).

Phase 10 - observability:
- Prometheus counters/gauges/histograms, GET /metrics, correlation IDs on
  every response, and an honest OTEL status endpoint.

Phase 11 - dashboard:
- A "Platform Engineering" view with five panels reading only live APIs.
  The existing logo and branding were not touched.

Phase 13 - CI/CD:
- .github/workflows/platform-engineering.yml with least-privilege
  permissions. Ruff blocks only on the new clean modules; the legacy tree
  is advisory. No deploy, publish or force-push step.

Phase 14 - tests: 485 passed, 0 failed. 31 new tests.
Phase 15 - the execution report and updated .env.example / README.

Honest limitations: CrewAI is installed but not executing via an LLM; MySQL
is implemented but unverified; no Grafana/Alertmanager, no ZAP/Snyk, no
self-healing; RBAC and the security defaults remain as previously decided.
